# Runtime/HPC reliability requirement-to-test matrix

Status: implementation, repository-wide non-live verification, explicitly opted-in real-SSH transport-only soak, and deployment rollback audit complete. The change is eligible for a separate operator-controlled `rxx` re-entry decision, but no numbered experiment was started. A row is proven only when its named deterministic tests pass and exercise the listed authority/fault seam. Passing an adjacent or broader smoke test does not close a row, and no live `rxx` result may fill a missing deterministic row.

Scenario count at baseline: 125 (`26` controlled execution, `33` continuation/runtime command, `28` quiescence/sealing, `38` runner).

Slices 0-4 code and deterministic tests are present and green. The landed tests cover schema versions 26-31, historical legacy reads, canonical repository identity/uniqueness/fencing, immutable dispatch/events/results/receipts/snapshots, closed transition properties, durable workers, attached-process delivery, `202` command polling, generic writer coverage, safe feature defaults, bounded shadow data, and a disabled-gate legacy-dispatch differential. The final evidence and re-entry decision are recorded in `implementation/final-verification-and-rxx-decision.md`.

## 5. Cross-cutting closure evidence

The following evidence is required in addition to each row's focused test:

1. Migration tests cover an empty database, upgrade from version 25, legacy-row classification, current-version verification, rollback-compatible reads, and downgrade rejection with active durable rows.
2. The cross-layer fault matrix joins Host operation id, execution id, approval digest, runner run id, RunSpec digest, dispatch generation, result handle, continuation delivery generation, mutation scope generation, and quiescence receipt; it asserts no identity drift at every boundary.
3. Public-secret scans cover runner responses, Host DTOs, durable public events, workspace/activity, `world.inspect`, health, AOX evidence, CLI, and UI/debug projections.
4. `task.finish` tests remain authoritative: capability/execution/result/delivery/command/quiescence terminal states never mechanically create a business task terminal state.
5. The final `rxx` re-entry decision consumes this matrix only after every row is backed by passing deterministic/focused/non-live evidence; a live attempt cannot fill a missing row.

## ADDED Requirements

### Requirement: Qualified claims require real-subject real-occurrence evidence
A `qualified` claim MUST enumerate exact capability, operation, route, real Provider or target subject, source, build and configuration digests, the actual Adapter or Driver bridge, occurrence authorization, terminal positive and negative observations, effect certainty, budget settlement, cleanup state and validity interval. Declaration, wheel, mount, non-live composition, recording fixtures, target reachability or a different successful operation MUST NOT satisfy this layer.

#### Scenario: SSH target is reachable but software smoke did not run
- **WHEN** identity discovery and transport observation succeed without the exact scientific operation terminal result
- **THEN** the route is not qualified for that scientific operation

#### Scenario: One real LLM turn succeeds
- **WHEN** its exact bounded occurrence and negative closure pass
- **THEN** only the bound LLM unit is qualified and no product-wide, cutover or future-live claim is emitted

### Requirement: Qualification and cutover remain independently authorized
Qualification completion MUST NOT update deployment selection, Session capability bindings, production credentials or live-by-default behavior. A later cutover workflow MUST consume only unexpired adopted qualification facts and MUST require its own change, deployment plan, authorization and cutover receipt.

#### Scenario: Every Batch 1 unit qualifies
- **WHEN** the qualification verifier accepts the complete exact receipt set
- **THEN** the system records qualification completion and performs no deployment adoption or cutover mutation

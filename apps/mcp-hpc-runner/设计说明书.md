# MCP HPC Runner 设计说明

## 目标

Runner 把 Host 已准入的 immutable workspace revision 安全转换为 Gitless compute tree，
并以一次性 scheduler occurrence credential 执行 SSH 或 Slurm job。它不解释文件业务含义，
不拥有 task/scientific terminal，也不提供通用文件发布边界。

## 请求身份

`executor_workspace_runspec@3` 绑定 workspace id/generation、repository binding、source
revision/ref/commit/tree、LFS closure、cwd、command/environment/resource digest、target、mode、
runner policy、exact target inventory generation/closure digest、controlled-operation identity、
scheduler occurrence 和 absolute deadline。

旧 input catalog、Host path、staging reference、declared output list、mutable branch-only source、
raw scheduler handle 和 arbitrary remote root 均为 closed unknown field，在任何外部 effect 前拒绝。

Runner 配置也是闭合的：只定义 transport、workspace、scheduler 和有界资源策略，
不接受按领域软件列出的 `[adapters.*]` catalog。软件版本、资产、数据库和 Driver
由 Tool Plugin requirement、operator qualification 产生的 target inventory 和 Distribution
显式选择共同决定。

## Source prepare

Runner 在 owner-qualified remote workspace 中验证 exact revision 和 LFS bytes，构造不含 `.git`、
Git/LFS binary、credential、endpoint 或 object locator 的 compute tree。cache key 包含 binding、
commit/tree/ref、LFS closure、target inventory generation/closure、owner、workspace generation、
runner policy 和 target。
首次准备后 runner 只持久化不可变 cache binding；后续命中必须通过保护 wrapper
`validate-source-cache` 返回 `verified_compute_tree_cache_validation@1` 新鲜校验回执。
cache binding、entry set 或校验回执的任何 drift 都以 `no_effect` 失败，不得改用
`prepare-source`、mutable login clone 或其他 snapshot。

## Authority

login/file credential 只允许 owner root 内原生 SSH/Git/LFS/rsync/scp/CRUD。scheduler submit
必须消费 Host 针对 exact occurrence 和 target 签发的一次性 credential。ambient `sbatch`、共享
account 或未登记 submit 在 scheduler 前拒绝。

## Lifecycle

public identity 是 opaque `run_id`。dispatch、reconcile、observe、logs、cancel 都绑定同一
occurrence。payload 可能已发出但 canonical receipt 未落盘时为 `dispatch_in_doubt`，禁止盲目
resubmit；restart/lease takeover 继续同一 handle 和 absolute deadline。

raw Slurm id、remote directory、SSH target/user、ControlPath、transport generation、private receipt、
raw command 和 credential 保持 runner-private。

## Output

普通输出留在 executor remote workspace。executor 自行检查、下载、整理、commit，并在需要时
显式 publish。Runner 不抓取某个文件集合、不自动 commit/publish，也不因某个 caller 期待的
filename 缺失而重写 backend terminal。可选 result revision link 是后续独立 control-plane fact。

## 安全与验证

所有 path 必须规范化且位于 owner root；禁止 symlink escape。错误显式区分 pre-effect、
in-doubt、terminal 和 reconciliation。默认测试为 non-live；真实 SSH/Slurm 需要独立配置与 opt-in。


# Multi-Agent Enzyme Design Framework (OpenCode + MCP + LangGraph)

本文档将本次对话的要点与细节系统整理，目标是把“自动/辅助酶设计”的想法从概念层落到可工程实现、可迭代优化的多智能体系统架构与技术栈上，并记录一个具体用例：缩小纤维二糖脱氢酶 CDH 的 DH（FAD 脱氢酶）结构域体积，同时必须保留 (1) 纤维二糖催化活性与 (2) 与 CYT 细胞色素结构域的电子传递能力。

---

## 1. 目标愿景（对话起点）

用户设想的 OpenCode Agent 酶设计系统能力链路：
- 通过 MCP 调用多种生物化学/生物信息学工具（需要在设计时明确工具清单）。
- 文献挖掘（先给出文献列表），提取与目标酶相关信息。
- 工具计算分析 -> 按需求改造 -> 调用蛋白语言模型生成 -> 计算评分评估。
- 人类反馈 -> 交付实验评估。
- 基于人类反馈与实验结果回流前面步骤，持续优化，输出新的候选序列与结果报告。

---

## 2. 关键诊断：为什么需要进一步细化

### 2.1 最大隐患：隐含“线性瀑布式流程”
对话指出：真实酶工程高度非线性。
- 文献挖掘可能在评估阶段才发现关键约束；实验结果可能推翻最初假设。
- Agent 应具备动态规划/状态机能力，而不是固定流水线。

### 2.2 蛋白语言模型（PLM）角色定位必须精细化
“调用蛋白语言模型生成”不能只是一个步骤，必须明确：
- 生成对象：点突变序列？局部重设计？逆折叠（给定骨架设计序列）？嵌合/域移植？de novo？
- 约束条件：保留基序/位点冻结/界面约束/保守性约束/多样性约束。
- 生成后筛选：如何用快速打分大幅过滤，如何做深度评估，如何输出不确定性。

---

## 3. 必须补齐的核心模块（对话总结的“系统缺失项”）

### 3.1 任务意图解析层（前端需求结构化）
需要把自然语言需求转为可计算“设计合同（design contract）”
- 目标分解：催化功能 / 底物特异性 / 稳定性条件（温度、pH、溶剂、盐等）/ 表达宿主 / 实验可行性约束。
- 设计策略选择：从头设计 vs 定向进化 vs 半理性设计。
- 成功标准量化：例如 kcat、Km、kcat/Km、转化率、ee、Tm、t1/2@T 等。

### 3.2 文献挖掘模块：必须输出结构化知识
不仅是“找到文献”，而要抽取并结构化：
- 活性位点与保守残基、关键氢键网络、辅因子配位。
- 突变先例：哪些位点突变致死，哪些位点有正向改造案例。
- 结构/序列-功能关系：残基组合与功能的关联。

建议工具方向（对话提及）：
- 文献/API：PubMed API、Semantic Scholar、bioRxiv。
- 信息抽取：BioGPT / PubMedBERT 等生物医学 NLP 模型辅助结构化抽取。

### 3.3 计算工具链：按设计阶段分层（而非笼统“工具计算”）
对话给出的分层示例：

结构预测层
- AlphaFold3 / ESMFold（示例）。
- RoseTTAFold All-Atom（含配体/辅因子建模时更关键）。

分子建模/模拟层
- Rosetta：能量最小化、突变 ddG (DeltaDeltaG)、重建/修复。
- Docking：AutoDock Vina / Glide（按需）。
- MD：GROMACS / OpenMM（深度评估，成本高）。

功能/约束预测层
- ProteinMPNN：序列设计（特别是逆折叠/局部重设计）。
- EVmutation / EVE：进化约束打分。
- 活性预测：CatPred / DLKcat（按任务适用性评估）。
- 稳定性预测：ThermoNet / mCSM（作为代理/预筛）。

可表达性预测层（常被忽略但工程很关键）
- 密码子优化、溶解性预测（CamSol）、信号肽预测等。

### 3.4 生成策略：多轨并行（conservative/moderate/aggressive）
对话建议三轨并行而不是单一路径：
- 保守轨：1-5 个位点小改造，低风险，优先送实验。
- 中等改造轨：重设计功能区域，保留骨架。
- 激进轨：de novo / 域嫁接，高风险高收益。
并可按实验资源分配比例（例如 60/30/10）。

### 3.5 评分体系：多目标帕累托 + 不确定性传播
对话强调：
- 真实场景稳定性与活性常矛盾，不能只做加权求和。
- 用多维评分向量（功能/稳定性/可表达性/新颖性或专利风险）。
- 用帕累托前沿筛选，并保留多样性。
- 输出置信区间或不确定性（而不是点估计）。

### 3.6 人类反馈接口：必须分流三类反馈
对话明确三类反馈处理逻辑不同：
1) 专家知识注入：更新知识库/约束库。
2) 实验结果反馈：用于校准预测偏差、更新模型/打分映射。
3) 优先级调整：改变策略/预算/实验资源分配，触发重规划。

## 4. 架构层改进：从“被动循环”到“可持续迭代系统”

### 4.1 设计记忆（Design Memory）/共享知识图谱
对话建议：
- 持久化每轮迭代的：候选、决策原因、淘汰原因、失败模式、工具输出、实验结果。
- 下一轮必须先查历史，避免重复探索已知死路。

### 4.2 不确定性驱动主动学习
对话观点：
- 不要每轮只推荐“最优预测”候选。
- 要主动识别哪个位点/哪个假设最缺数据，优先推荐信息量最大的实验组合。
- 可用主动学习/贝叶斯优化思路减少实验轮数。

### 4.3 工具调用的失败处理与降级策略
对话指出：外部工具可能失败/不收敛/无结果。
- 需要在架构层定义重试/降级/备用工具/置信度下调策略树。

### 4.4 容易被低估的难点（对话明确提醒）
- 序列多样性 vs 质量：PLM 生成的候选若高度相似，一次失败可能全军覆没。要显式多样性约束（相似度矩阵 + 聚类采样）。
- 计算预测与实验系统性偏差：例如 Rosetta ddG (DeltaDeltaG) 与实验相关性有限，需要在线校准而不是盲信。
- 安全/监管检查：涉及敏感底物/用途时必须有安全审查节点。

---

## 5. 推荐总体流程（对话给出的“更完整流程图”文字版）

1) 任务意图解析
2) 策略规划：选择设计轨道 + 量化成功标准
3) 并行信息收集
   - 文献结构化挖掘 -> 约束数据库
   - 同源序列分析 -> 进化约束
   - 已有结构检索 -> 骨架库
4) 多轨并行设计（保守/中等/激进）
5) 多层计算评估 -> 帕累托筛选 -> 带置信区间的候选列表
6) 主动学习推荐实验组合
7) 人类审查（反馈分流）
8) 实验结果摄入 -> 校准 -> 更新设计记忆
9) 迭代规划：继续/收敛/切换策略

## 6. 多智能体（Multi-Agent）架构评审与改进

### 6.1 初始 4-Agent 提案与收益
对话讨论的初始角色：
- Researcher：文献/数据库挖掘。
- Designer：序列/结构生成。
- Evaluator：计算与评估。
- Manager：调度与汇总。

收益：上下文隔离、并行执行。

### 6.2 4-Agent 方案问题（对话逐条指出）
- Evaluator 负载不均：对接分钟级、MD 天级，串在一起会成为瓶颈。
- Researcher 输出若是自由文本，Designer 难以直接使用，必须结构化。
- Manager 不能只是路由器，必须是动态决策/状态机。
- 缺少实验反馈专职角色：需要 Experimentalist 处理湿实验数据回流和校准。

### 6.3 调整后的推荐架构
角色集合（对话建议）：
- Manager Agent：项目状态机 + 动态规划 + 决策。
- Researcher Agent：文献/DB 结构化抽取，产出约束库。
- Designer Agent：在约束下生成候选，三轨并行 + 多样性控制。
- Fast-Screen Agent：序列层面秒级预筛，大幅过滤。
- Deep-Eval Agent：结构模拟/MD/对接等深度评估（少量候选）。
- Experimentalist Agent：解析实验数据、识别系统偏差、在线校准。

共享中间件：中央状态存储/知识图谱（约束库 + 历史记录）。

工程实现注意点（对话强调）：
- Agent 间通信协议要标准化（避免格式不匹配）。
- 失败传播机制要设计清楚（重试/降级/上报）。
- 人类介入点要提前定义（送实验前、意外结果时等）。

## 7. 技术栈选型：OpenCode vs LangGraph（对话结论）

### 7.1 两条路线的哲学差异
- OpenCode Markdown/skills/commands：偏“自然语言定义 Agent 行为”，开发快但难测试、难强约束。
- LangGraph：偏“代码定义状态机”，可控可测试，适合复杂工作流。

### 7.2 对话推荐的分层组合（更适合酶设计）
流程编排层：LangGraph
- 显式状态机、并行分支、人类介入节点。
- 状态用 Pydantic 强类型，统一数据格式。

Agent 推理层：LLM API（示例提及 Claude/OpenAI）
- 每个专家 Agent 在受限工具集合中推理。

工具封装层：MCP Servers（Python）
- 把 Rosetta、GROMACS、AlphaFold、UniProt 查询等封装为独立可测试服务。

知识持久化：结构化存储
- PostgreSQL + pgvector（或 MVP 用 SQLite）。
- 可选 Neo4j 做知识图谱。

调试追踪：LangSmith（或同类 tracing）

## 9. 具体用例：缩小 CDH 的 DH 结构域体积（必须保活性 + 保 ET）

### 9.1 用户目标
- 目标：缩小纤维二糖脱氢酶 CDH 的 DH（FAD 脱氢酶）结构域体积。
- 结构输入：PDBID `4QI6`。
- 硬约束：必须保留
  1) DH 对纤维二糖的催化活性
  2) 与 CYT 结构域的电子传递能力

### 9.2 本次对话检索到的关键结构/序列信息（用于约束与建模）
来自 RCSB/UniProt 交叉引用（A9XK88）：
- 蛋白：MtCDH（Thermothelomyces myriococcoides / Myriococcum thermophilum）
- UniProt：`A9XK88`
  - signal peptide：1-21
  - chain：22-828
- 结构域边界（对话中作为工作假设）：
  - CYT：约 23-229
  - linker：约 230-243
  - DH：约 244-791
  - CBM1：约 792-828
- 同论文相关 PDB：`4QI3`, `4QI4`, `4QI5`, `4QI6`, `4QI7`, `4QI8`
  - `4QI4/4QI5` 含 DH+CBM（244-828），分辨率更高，适合提取 FAD 口袋几何与冻结位点。
  - `4QI6` 含 CYT+DH（全长 22-828），适合提取 CYT-DH 界面与相对构象。

辅因子/修饰特征（来自 UniProt `A9XK88` 的 PDB 证据注释，用于冻结/禁删约束的候选来源）：
- Heme b 结合相关位点（CYT 侧为主）：例如 95、120、197（并有 Mg(2+) 170/207 的注释）。
- FAD 结合相关位点（DH 侧）：例如 260、261、280、334、338、343、345、461、759、771（用于定义 FAD 邻域冻结集的种子/核对点）。
- 糖基化位点：存在多处 N-linked / O-linked 位点注释（例如 N140、T216/T218/T225/T227/T247、N421、N458、N537、N699）。
- 二硫键：存在多对二硫键注释（包括 CBM1 区域的二硫键），在“可删段”方案中通常应默认禁删/禁破坏。

备注：上述位点编号为 UniProt 序列编号（含 signal peptide），建模/约束时需要做 UniProt-PDB 编号映射与域边界一致性校验。

主要文献（RCSB primary citation）：
- Tan TC et al. Nat Commun (2015) "Structural basis for cellobiose dehydrogenase action during oxidative cellulose degradation." DOI: 10.1038/ncomms8542

UniProt 关联参考：
- Zamocky M et al. Protein Expr. Purif. (2008) DOI: 10.1016/j.pep.2008.02.007

### 9.3 为什么“缩小”在此用例中必须双重约束（活性 + ET）
对话明确：这不是单纯裁剪环区。
- 活性：必须保留 FAD 结合口袋与催化几何。
- ET：必须保留 CYT-DH 界面与能达到电子传递构象的能力。

因此，任何“删除/替换”必须避开：
- FAD 邻域冻结区
- CYT-DH 界面冻结区
- 关键结构支撑（核心二级结构、二硫键等）

### 9.4 需要定义的可计算目标与验收指标（对话建议落地化）
体积/尺寸指标（建议至少两个同时作为主目标）：
- DH convex hull volume（244-791）
- DH Rg / 最大直径
辅助指标：SASA、形状描述符。

功能/ET 代理指标（计算层）：
- 活性代理：FAD 口袋几何保持、底物通道未塌陷（必要时对接/口袋体积作为辅助）。
- ET 代理：CYT-DH 界面接触图相似度、heme(Fe)-FAD(isoalloxazine) 距离/取向代理、闭合构象可达性。

实验验收指标（系统应输出实验建议模板）：
- 纤维二糖氧化活性测定（如 DCIP 等电子受体体系，按实验室 SOP 定义）。
- 电子传递能力测定（heme 还原/氧化动力学、对外部受体转移能力、或 LPMO 驱动能力等按资源选择）。

### 9.5 结构化约束集（Researcher 输出必须是机器可用）
建议把约束拆成三类冻结集：

Frozen set A（活性核心）：
- 从 `4QI4/4QI5` 提取 FAD 邻域残基（距离阈值 X A）。
- 这些残基禁止删除；突变仅允许保守替换或完全冻结。

Frozen set B（ET/界面）：
- 从 `4QI6` 提取 CYT 与 DH 的界面残基（距离阈值 X A 或接触图）。
- 禁止删除；突变受限；界面形状保持作为评分项。

Frozen set C（结构完整性）：
- 二硫键、核心结构元件。
- 糖基化位点与糖链是否计入“体积目标”属于待明确项（本次对话留为开放问题）。

### 9.6 三条并行设计路线（对话针对该用例的建议）

路线 A（低风险，小幅缩小）：可删环/可删插入片段
- 用同源 MSA 找 DH 中低保守的插入片段/长环。
- 结构过滤：远离 Frozen A/B；端点几何适合闭合。
- 删除后通过 ProteinMPNN/逆折叠模型生成“补洞闭合”多样序列。

路线 B（中风险，中幅缩小）：段替换
- 把“长段”替换为同源中更短对应段，并局部重设计连接区。
- 相比纯删除，更可能保持折叠与功能。

路线 C（高风险，大幅缩小）：更紧凑骨架/嵌合
- 在保持活性口袋特征 + 界面补丁的硬约束下，尝试更紧凑的 GMC/AA3 类骨架。
- ET 保持难度更高，应作为最后策略。

### 9.7 分层评估（避免 Deep-Eval 成为瓶颈）
Fast-screen（秒级）：
- 约束合规（冻结位点/禁止删除区）。
- 序列可表达/溶解/无序风险代理。
- 多样性约束（聚类取样）。

Mid-screen（分钟级）：
- DH-only 结构预测。
- DH 体积/Rg 计算。
- FAD 口袋几何检查。

Deep-eval（小时-天级，仅少量）：
- CYT+linker+DH 结构/构象评估。
- 界面接触图相似度/界面 RMSD。
- heme-FAD 距离/取向代理。
- 必要时短 MD 检查闭合态可达性。

### 9.8 MCP 工具清单（围绕该用例的最小可行集合）
文献/DB：
- PubMed / Semantic Scholar 检索与结构化抽取。
- UniProt `A9XK88` 特征拉取。

同源与约束：
- BLAST/MMseqs2、MAFFT/HMMER；插入片段检测与保守性评分。

结构与几何：
- RCSB PDB 拉取与解析（mmCIF/PDB）。
- 域切割（244-791），界面残基提取（CYT vs DH），FAD 邻域残基提取。
- 体积/Rg/最大尺度计算；口袋几何检查。

生成与重设计：
- ProteinMPNN（支持冻结残基、局部设计、闭环补洞）。
- 可选 ESM-IF（逆折叠）或 Rosetta Remodel/Loop closure。

打分与选择：
- 多目标帕累托筛选。
- 多样性约束（相似度矩阵 + 聚类）。
- 不确定性标注与 OOD 检测。

实验回流：
- 结构化摄入实验数据（序列ID、协议ID、原始读数、拟合参数、误差、失败原因）。
- 批次效应/质控与在线校准。

### 9.9 本次对话记录的开放问题
在最后一步，系统仍需用户明确一个关键点（当时尚未回答）：
- “缩小”是否仅针对蛋白骨架（不含糖链/不含 CBM1），还是必须连糖基化导致的外形尺寸也要缩小。
对话建议默认先按“骨架体积”为主目标，并将糖基化作为次级目标/风险项报告，除非明确要求。

## 10. 下一步可执行落地（按对话建议的 MVP）

建议先实现该 CDH 用例的最小闭环：
1) 拉取 `4QI4/4QI5/4QI6` 与 `A9XK88`；固定域边界。
2) 自动生成 Frozen A/B（FAD 邻域 + CYT-DH 界面）。
3) 生成候选删除库（低保守、远离冻结区、可闭合的环/插入）。
4) 对每个删除方案生成多样“补洞闭合”序列（固定冻结位点）。
5) DH-only 结构预测 -> 体积/Rg -> FAD 口袋检查 -> 预筛。
6) 对 Top K 做 CYT+DH 几何与界面/ET 代理评估。
7) 输出报告：帕累托前沿 + 多样性簇 + 实验包（exploit+explore）。
8) 摄入实验结果并校准，进入下一轮。
